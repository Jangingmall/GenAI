## 한 줄 요약

**BE 는 작업 제출 후 31분 안에 콜백이 온다고 가정하는데, 저희는 장인이 승인할
때까지 콜백하지 않습니다. 장인이 초안을 31분 넘게 보면 정상 작업이 `FAILED` 로
찍힙니다.**

---

## 1. 지금 무슨 일이 일어나는가

### 저희 파이프라인

```
작업 접수(202) → 분석 → DRAFT_READY  ← 여기서 멈춥니다
                            ↓
                      장인 승인(approve)
                            ↓
                    렌더 → 콜백 → COMPLETED
```

`DRAFT_READY` 는 **초안이 준비된 상태이지 완료가 아닙니다.** 장인이 사진 구성과
카피를 보고 승인해야 그다음이 진행됩니다.

### BE 의 가정

`GenerationDeadlineScheduler` 가 **1861초(약 31분)** 동안 콜백이 오지 않은
generation 을 `FAILED` 로 바꿉니다.

### 부딪히는 지점

2026-09-21 연동 테스트에서 실제로 관측했습니다. 저희 분석이 `DRAFT_READY` 로
끝난 뒤에도 BE 는 계속 `QUEUED` 였습니다.

```
GET /api/content/products/1/generations/1
{"generationId":1,"productId":1,"status":"QUEUED","completedAt":null}
```

**이 상태로 31분이 지나면 `FAILED` 가 됩니다.** 저희 파이프라인은 아무 문제 없이
초안을 만들어 두고 승인을 기다리는 중인데도 그렇습니다.

### 31분이 왜 부족한가

장인이 하는 일은 사진 8장의 구성과 카피 전체를 보고 고치는 것입니다. 상품 등록
중에 다른 일이 생기면 쉽게 넘어갑니다. **사람 검수 시간을 31분으로 묶는 것은
현실적이지 않습니다.**

참고로 저희 생성 시간 자체는 짧습니다. 로컬 실측 기준 60건 평균 **254초(약 4분)**
이고 최대 312초였습니다. **기계가 쓰는 시간은 데드라인의 1/7 밖에 안 됩니다.
남은 27분이 사람 몫인데, 그게 부족한 것입니다.**

## 2. 정해 주셔야 할 것 — A / B / C

### A. 초안 시점에 콜백하고, 승인은 BE·FE 에서 (저희 의견)

```
작업 접수(202) → 분석 → DRAFT_READY → 콜백 → BE 가 초안 보관
                                              ↓
                                        FE 에서 장인이 검토·승인
```

| | 내용 |
| --- | --- |
| BE 작업 | 초안 상태를 받아 저장하고 FE 에 표시. 승인 처리 흐름 추가 |
| AI 작업 | 콜백 시점을 렌더 뒤에서 초안 뒤로 앞당김 |
| 데드라인 | **31분 그대로 둬도 됩니다.** 기계 시간(약 4분)에만 걸립니다 |
| 장점 | 사람 검수 시간에 제한이 없어짐. 데드라인이 본래 목적(AI 장애 감지)대로 동작 |
| 단점 | BE·FE 에 승인 화면·상태가 필요 |

**저희가 A 를 권하는 이유**는 역할 구분입니다. 초안을 만드는 것까지가 AI 의
일이고, 사람에게 보여주고 승인받는 것은 **화면이 있는 쪽**에서 하는 일이라고
봅니다. 저희에게는 장인에게 보여줄 화면이 없습니다.

### B. 승인을 자동화한다 (초안 = 최종)

| | 내용 |
| --- | --- |
| BE 작업 | 없음 |
| AI 작업 | 승인 단계 제거, 분석 후 바로 렌더·콜백 |
| 데드라인 | 그대로 둬도 됨 |
| 장점 | 양쪽 변경이 가장 적음 |
| 단점 | **장인이 초안을 고칠 수 없습니다** |

**이건 제품 결정입니다.** AI 가 만든 카피와 사진 구성이 장인 확인 없이 그대로
상품 페이지가 됩니다. 저희 안전성 검증에서 **사진과 어긋난 판매자 입력이 그대로
카피에 들어가는 것**을 확인했으므로, 사람 확인 없이 내보내는 것은 권하지
않습니다.

### C. 현행 유지 + 데드라인 연장

| | 내용 |
| --- | --- |
| BE 작업 | 데드라인 값을 사람 검수 시간에 맞춰 조정 |
| AI 작업 | 없음 |
| 장점 | 지금 구조를 안 바꿔도 됨 |
| 단점 | **데드라인이 안전망 역할을 못 합니다** |

수 시간으로 늘리면 AI 가 실제로 죽었을 때도 그만큼 방치됩니다. 데드라인을 넣으신
본래 목적과 어긋납니다.

## 4. 회신 부탁드립니다

**A / B / C 중 하나만 알려 주시면 됩니다.**

- **A** 로 정해지면 저희 쪽 변경(콜백 시점 이동)은 **하루 안에** 끝납니다.
  BE·FE 의 승인 화면 일정만 알려 주시면 거기 맞추겠습니다.
- **B** 는 제품 담당자 확인이 필요합니다. 승인 단계를 없애는 결정입니다.
- **C** 로 가시면 데드라인을 몇 분으로 하실지 함께 알려 주세요.

정해지기 전까지 저희는 **현행 흐름을 유지**합니다. 연동 테스트에서는 승인을 즉시
수행해 확인하고 있어, 지금은 데드라인에 걸리지 않습니다. **실제 장인이 쓰기
시작하면 그때부터 문제가 됩니다.**
