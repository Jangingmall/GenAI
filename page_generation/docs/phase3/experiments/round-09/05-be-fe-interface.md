## 1. BE 계약 변화

### 1) 다양성이 확보된 page_plan 출력
백엔드 파이프라인이 6건 전체에 걸쳐 완전히 상이한 6종의 고유 블록 시퀀스를 FE로 전달한다 (유효 공통 블록 0종, 완전 일치 0쌍).

### 2) DTO 스키마 무변경 원칙 고수
선택된 레이아웃 원형의 ID를 전달하기 위해 DTO 스키마에 신규 필드를 뚫지 않았다. `src/detail_page_ai/layout_archetypes.py`의 `match_selected_archetype()` 헬퍼 함수가 FE로 내려보내기 전 사후 분석에만 사용되므로, BE-FE 간의 DTO 인터페이스 스키마는 5차 이후 완벽히 동일하게 유지된다.

## 2. 계약상 결함: react_document 내 '참고용' 라벨 누락 (사용자 결정에 의해 미수정, 기록만 함)

### 1) 산출물 계약 탈락
`src/detail_page_ai/source_photos.py:793`, `:834`에서 생성 이미지에 `label="AI 생성 활용 장면(참고용)"`, `label="AI 생성 디테일(참고용)"`을 붙여 `result_summary.json`에는 케이스당 5회 정상 기록된다. 그러나 우리 팀 코드인 `src/detail_page_ai/react_document_builder.py:224-232`가 이미지 노드를 생성할 때 `PhotoAsset.label`을 싣지 않고 `alt`만 합성하여 내보낸다. 

### 2) FE 계약에 데이터 부재
이로 인해 우리가 FE로 넘기는 `react_document.json`에는 '참고용' 문자열이 전수 실측 0회로 완전히 누락되어 있다 (9차 6건 전부 실측 확인). 이는 FE 렌더러의 컴포넌트 미구현 문제가 아니라, 백엔드 빌더가 FE가 렌더링할 데이터 필드 자체를 계약에서 떨어뜨려 전달하지 않는 명백한 계약상 결함이다.

### 3) 조치 및 상태
사용자 결정에 의해 이번 스프린트에서는 코드를 수정하지 않고 **미수정(기록만 함)**으로 유지하며, 상용 릴리스 차단(blocker) 조건으로 관리한다.

## 3. 하위 호환성 여부
**기존 스키마 하위 호환 유지**. DTO 스키마 및 react_document 노드 구조 자체는 기존 클라이언트와의 하위 호환성을 유지하고 있으나, 법적/규제성 라벨 전달 계약이 누락된 상태이다.
