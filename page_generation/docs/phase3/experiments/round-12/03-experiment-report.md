## 1. 문제와 판정 범위

12차는 판매 상품 사진에 rembg 누끼를 적용하고, hero에는 원본을 고정하며, 생성 사진의 '참고용' 표시를 제거한 뒤, 누끼와 생성 배경을 합성하는 대안을 대조한 차수였다. 입력은 1060×1060 나전칠기 상자 사진과 1060×1060 반투명 꽃잎 장식 사진이었다.

이번 차수의 구조 다양성 파일럿 실행과 사람 검수 점수는 정본에 기록되어 있지 않다. 구조 지표는 아래에서 `확인 필요`로 남겼고, rembg 채택은 관리자의 육안 판정 "잘땄네"로 기록했다.

## 2. 실험 A — 기존 추출기와 rembg 62케이스 비교

### 문제

기존 추출기는 판매 상품 사진과 박물관 사진을 같은 방식으로 처리할 때 누끼 성공 범위와 반투명 제품 전경 보존에 한계가 있었다.

### 가설

기존 추출기와 rembg를 같은 62케이스에 적용하면 rembg의 누끼 성공 범위와 반투명 꽃잎의 전경 보존 차이를 확인할 수 있을 것이다.

### 실험 설계

- **변경 요소**: 누끼 추출기를 기존 방식에서 rembg `birefnet-general`로 바꾸었다.
- **고정 요소**: 60건 저장 사진과 판매 사진 2건을 사용했다. 각 케이스에 `old.png`와 `rembg.png`를 만들었다.
- **산출물**: `generated/cutout-compare/`.
- **실행 명령**: 정본에 전체 실행 명령이 없어 확인 필요.

### 결과

| 항목 | 기존 추출기 | rembg |
| --- | ---: | ---: |
| 누끼 성공 | 11/62건 (60건 중 9건 + 판매 사진 2건) | 62/62건 |
| 빈 마스크 | 확인 필요 | 0건 |
| 전체 마스크 | 확인 필요 | 0건 |
| 꽃잎 전경비율 | 6.1% | 21.9% |

판매 상품인 나전칠기 사진의 원본 모서리 밝기는 240/216/238/216이었고 최대 편차는 12.5였다. 기존 추출기 임계값 24를 통과해 배경 제거에 성공했다. 비교 대상인 미술관 사진 60건의 모서리 편차 중앙값은 101.3이었다.

### 판정

관리자가 rembg 결과를 육안으로 보고 "잘땄네"라고 판정하여 rembg를 채택했다. 이는 사람 검수 점수가 아니라 관리자 판정 문구다.

### 가설 검증 결과와 남은 한계

62케이스 성공 수와 꽃잎 전경비율의 차이는 관찰되었고 rembg 채택으로 이어졌다. 케이스별 정량 시각 품질 점수와 사람 검수 점수는 존재하지 않는다.

## 3. 실험 B — rembg 2.0.69와 2.0.83 마스크 동일성

### 문제

rembg 버전을 2.0.69로 고정하면서 비교에 사용한 2.0.83과 마스크 결과가 달라지는지 확인할 필요가 있었다.

### 가설

기준 6장에서 rembg `2.0.69`와 `2.0.83`의 알파 마스크가 같다면 Pillow 11을 유지하고 rembg `2.0.69`를 잠글 수 있을 것이다.

### 실험 설계

- **변경 요소**: rembg 버전만 `2.0.69`와 `2.0.83`으로 바꾸어 마스크를 대조했다.
- **고정 요소**: nacre, petals, `cma-109609`, `cma-165271`, `cma-122443`, `cma-168479`의 6장을 사용했다.
- **실행 명령**: 정본에 비교 실행 명령이 없어 확인 필요.

### 결과

6장 모두에서 알파 차이는 `0`이었다. 최종 의존성은 rembg `2.0.69`, Pillow `11.3.0`, NumPy `2.5.3`, onnxruntime `1.29.0`으로 잠갔다.

### 판정

6장 기준 마스크 동일성 검증 결과를 근거로 rembg `2.0.69`를 채택하고 Pillow를 올리지 않았다.

### 가설 검증 결과와 남은 한계

가설은 기준 6장에서 알파 차이 `0`으로 입증되었다. 비교 범위는 정본에 기록된 6장이며, 그 밖의 케이스 차이는 확인 필요다.

## 4. 실험 C — 누끼+생성배경 합성 시도

### 문제

관리자 지시인 "rembg로 누끼 따고 배경합성"을 현재 활용 장면 경로에 적용할 수 있는지 확인했다. 기존 파이프라인에서는 누끼 성공 시에도 lifestyle에 `_generated_usage_scene`의 Flux 생성 결과를 먼저 사용하고, 누끼+생성배경 합성은 그 실패 시 예비 경로였다.

### 가설

누끼 제품을 생성 배경에 합성하면 lifestyle을 `source_composite`·`background_generated=True`·`product_generated=False`로 만들 수 있을 것이다.

### 실험 설계

- **변경 요소**: lifestyle 기본 경로를 생성 배경+누끼 합성으로 바꾸고, 실패 시 Flux 편집, 그 다음 단색 합성을 사용하도록 시도했다.
- **프롬프트 변경**: `background-v4-jewelry-coverage`에서 `background-v5-front-facing-composite`로 바꾸었다. v5에는 빈 바닥면, 정면·아이레벨, 부드러운 조명, 하단 중앙 제품 영역을 넣었다.
- **고정·범위**: detail-02~05는 이 시도의 범위 밖이었다.
- **산출물**: `generated/composite-check/nacre`, `generated/composite-check/petals`.
- **실행 명령**: 정본에 합성 검증 실행 명령이 없어 확인 필요.

### 결과

| 관찰 항목 | 관리자 앞 육안 소견 |
| --- | --- |
| 제품 형태 | 정확했다. |
| 배경 | 두 상품 모두 배경이 거의 같은 흰 원판으로 수렴했다. |
| 꽃잎 시점 | 위에서 본 원본 꽃잎을 정면 배경 앞에 세워 붙여 시점이 맞지 않았다. |

합성 확인 시간은 나전칠기 `322.13초`, 꽃잎 `267.83초`였다. 테스트는 시도 시점에 `350 passed`였다.

### 판정

오케스트레이터가 비교 페이지에 위 세 가지 소견을 적어 제시했고, 관리자는 이를 본 뒤 별도 이유를 밝히지 않고 선택지 2를 결정했다. 합성 시도는 반려되었고, 미커밋 `src/detail_page_ai/source_photos.py`, `src/detail_page_ai/prompts.py`, `tests/test_source_photos.py`를 `cfd60bb`로 되돌렸다. prompt v4와 Flux 활용 장면 생성 경로를 유지했으며, 되돌린 뒤 테스트는 `348 passed`였다.

### 가설 검증 결과와 남은 한계

누끼 제품을 생성 배경에 놓는 결과를 생성하고 제품 형태 정확성은 확인했지만, 관리자 판정에 따라 대안은 채택되지 않았다. 반려에 대해 기록된 것은 오케스트레이터가 제시한 세 가지 소견과 관리자의 선택지 2 결정까지이며, 그 밖의 이유는 확인 필요다.

## 6. 차수 판정과 남은 한계

hero 원본 고정과 rembg 누끼는 채택되었고, 생성 사진의 표시 문자열과 `react_document` 라벨 노드는 제거되었다. 누끼+생성배경 합성은 오케스트레이터가 제시한 세 가지 소견을 관리자가 본 뒤 선택지 2를 결정해 반려되었다.
