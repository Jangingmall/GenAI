## 1. 문제
Round 06의 카탈로그 25종에는 `sand`가 39회나 배정되어 있었으나, 프롬프트가 `variants`를 싣지 않아 실제 출력에서 `sand 0`으로 전멸했다. 코드가 블록 구성을 결정해도 스타일은 모델이 `paper`와 `light` 위주로 되돌려놓고 있었다.

## 2. 가설
선택된 원형의 블록별 variant를 프롬프트에 명시하고 모델이 이를 따르도록 지시하면, 카탈로그의 variant 분포가 출력에 고르게 반영되어 `sand`와 `compact`도 실제로 활용될 것이다. 단, 블록 선택 로직은 불변이므로 구조 지표(평균 Jaccard 등)는 Round 06과 크게 다르지 않을 것이다.

## 3. 실험 설계
- **변경 요소**:
  - `src/detail_page_ai/prompts.py`: 프롬프트에 블록 시퀀스와 함께 variant 매핑 주입.
  - 실행 옵션: 고속 구조 측정을 위해 `--image-provider none` 플래그로 AI 이미지 생성 모델 비활성화.
- **통제 요소**:
  - 이미지 해시 기반 단일 원형 선택 메커니즘 유지.
  - 카탈로그 원형 25종 및 validation 정규화 규칙 유지.

## 4. 실행 명령 및 환경
- 실행 디렉터리: `generated/evaluation/pilot-20260910-153208`
- 실행 환경: `--image-provider none` (AI 이미지 생성 없음, 케이스별 `image_model: none`, 소요 시간 11.0분)
- 메타데이터 주의: `run_index.json` 최상위의 `image_model`은 설정값(flux2)으로 표기되나 실제 케이스별 `image_model`은 `none`이다.

- 성공 5건의 46개 블록 variant 분포:

### 2) 예상대로의 입증: 구조 지표 불변
