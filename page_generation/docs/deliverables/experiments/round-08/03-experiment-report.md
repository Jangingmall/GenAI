## 1. 문제
Round 07까지 구조 수렴 문제는 지속되었고, 시뮬레이션 결과 개정 전 카탈로그의 이상적 추출 상한선이 63.9%임이 밝혀졌다. 반면 당시 합격 기준은 60% 이하, 고정 블록 포함 4종 이하, 0쌍으로 카탈로그로는 도달 불가능한 목표였다. 또한 카탈로그 자체도 4대 블록(`notice, info_table, detail_split, usage_scene`)이 84~96%의 원형에 붙어 있어 구조 다양성을 원천 차단하고 있었다.

## 2. 가설
카탈로그 원형에서 조건에 맞지 않는 4대 붙박이 블록을 완화하면 카탈로그 기준선이 55% 수준으로 낮아질 것이다. 또한 합격 기준을 카탈로그 비복원 추출 시뮬레이션 평균 + 10%p로 현실화하고 고정 블록(`hero, closing`)을 유효 공통에서 제외하면, 파이프라인의 다양성이 도달 가능한 기준선 내에서 정당하게 평가받을 수 있을 것이다.

## 3. 실험 설계
- **변경 요소**:
  - `assets/references/detail-page-layouts.json`: 4대 붙박이 블록을 원형 성격에 따라 선별 제거하고 저빈도 블록 보강.
  - `scripts/check_plan_diversity.py`: 시뮬레이션 기반 동적 Jaccard 기준, 유효 공통 블록, 완전 일치 <= 1쌍 게이트 구현.
  - 실행 옵션: 고속 구조 측정을 위해 `--image-provider none` 플래그로 AI 이미지 생성 모델 비활성화.
- **통제 요소**:
  - 해시 기반 단일 원형 선택 로직 유지.

## 4. 실행 명령 및 환경
- 실행 디렉터리: `generated/evaluation/pilot-20260910-161310`
- 실행 환경: `--image-provider none` (AI 이미지 생성 없음, 케이스별 `image_model: none`, 소요 시간 11.7분)
- 카탈로그 시뮬레이션 결과: 개정 카탈로그 지정 시뮬레이션(seed 0, 3000회) 54.44%, 현재 스크립트 기준선 54.52% (임계값 64.52%).
- 메타데이터 주의: `run_index.json` 최상위의 `image_model`은 설정값(flux2)으로 표기되나 실제 케이스별 `image_model`은 `none`이다.

## 7. 가설 검증 결과

### 1) 완전 입증: 카탈로그 상한 및 유효 공통 완화
카탈로그 붙박이 블록을 걷어내자 시뮬레이션 상한선이 63.9%에서 54.4%로 내려갔고, 실제 출력의 유효 공통 블록도 4종에서 1종(`wide_image`)으로 격감했다.

### 2) 반증: 기준 개정만으로 통과 불가
카탈로그와 판정 기준을 도달 가능한 현실적인 값으로 고쳤음에도 8차 결과물은 평균 Jaccard(66.01% > 64.52%)와 완전 일치 쌍(2쌍 > 1쌍)에서 탈락했다. 원형을 선택하는 메커니즘을 바꾸지 않고 기준만 완화하면 파이프라인이 통과할 것이라는 안이한 기대는 반증되었다.
