## 문제

9차까지 생성 사진의 `참고용` label이 `result_summary.json`에는 있었지만 `react_document.json` 계약에는 0회 전달됐고, 60건 전체 평가도 아직 같은 조건으로 확인되지 않았다. 10차는 라벨 전달 계약을 수정한 뒤 전체 60건을 실행해 라벨 게이트와 구조 다양성 표본을 확인했다.

## 가설

생성 사진 metadata를 React 문서 빌더와 HTML renderer에 전달하면 생성 사진에는 `참고용` label이 표시되고 원본 사진에는 표시되지 않을 것이다. `--all` 실행으로 매니페스트 60건을 순회하면 60건 실행 성공 여부와 라벨 게이트를 확인할 수 있고, 구조 다양성은 기존처럼 카테고리당 1건 6건 표본에 적용하면 산술적으로 같은 기준을 유지할 수 있을 것이다.

## 실험 설계

- **변경 요소**:
  - `build_react_document_from_draft(draft, *, generated_photos=None)`를 추가하고 `product_generated=True` 사진만 label 대상으로 삼았다.
  - pipeline에서 사진 metadata 생성 뒤 React 문서를 만들도록 순서를 이동했다.
  - HTML renderer에 생성 사진 figcaption과 기존 CSS 토큰 기반 표시를 추가했다.
  - 평가 러너에 `--all`, `--limit`, `--resume`, 증분 원자적 `run_index.json` 기록과 이미지 실행 메타데이터를 추가했다.
- **통제 요소**:
  - 10차 정본의 평가 디렉터리와 모델 설정을 사용했다.
  - 텍스트 모델은 `ddalcu/Qwen3.8-27B-MLX-Serve-4bit`, 이미지 provider는 `mlx`, 이미지 모델은 `mlx-community/flux2-klein-9b-4bit`였다.
  - 라벨 게이트는 생성 사진과 원본 사진을 구분했다.
- **다양성 표본 설계**:
  - 다양성 게이트는 60건 통짜가 아니라 카테고리당 1건씩 6건 표본에 적용했다.
  - 기존 임계값은 6건 비복원 추출의 기대치로 계산됐기 때문에 60건 전체에 그대로 적용하면 표본 크기가 달라 산술이 맞지 않았다.

## 실행 명령

- 실행 모드: `scripts/run_eval_pilot.py --all`
- 실행 산출물: `generated/evaluation/full60-20260910-204433`
- 저장된 `run_index.json`에는 전체 실행의 모든 CLI 인자가 보존되어 있지 않아, `--all` 이외의 전체 원문 명령은 확인 필요로 남겼다.
- 라벨 게이트는 `scripts/check_reference_label.py`로 같은 케이스를 수정 전·후 비교했고, `analysis-cma-102980`은 수정 전 FAIL(종료 코드 1), 수정 후 PASS(종료 코드 0)였다.

## 그 차수가 입증하거나 반증한 것

### 입증한 것

- 생성 사진 metadata를 builder에 전달하는 계약 수정이 `react_document.json`의 label 누락을 해소했다. 생성 사진만 figcaption을 받고 원본 사진은 label을 받지 않았다.
- 증분 `run_index.json`과 `--all` 실행으로 60건 전건을 성공적으로 기록할 수 있었다.
- 6건 표본에 대한 구조 다양성 수치는 52.3%, 유효 공통 0종, 완전 일치 0쌍으로 PASS였다.

### 입증하지 못한 것

- 6건 표본의 다양성 판정은 60건 전체의 다양성을 직접 판정하지 않는다.
- 컷아웃 게이트의 부분 손실 5건은 남아 있어 모든 이미지 품질이 통과했다고 입증하지 못했다.
- 고유 원본이 59종이므로 60개 입력이 60개 서로 다른 제품을 의미한다고 입증하지 못했다.
- 사람 검수 점수나 전반적인 상품성·시각 품질은 평가하지 않았다.
