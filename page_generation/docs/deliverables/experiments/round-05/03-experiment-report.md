# Round 05 · Experiment Report — 코드가 구성하고 모델이 카피 작성

| 항목 | 값 |
| --- | --- |
| 차수 | 05 |
| 파일럿 디렉터리 | `generated/evaluation/pilot-20260910-135605` |
| 직전 차수 기준 | `generated/evaluation/pilot-20260910-123917` |
| 이미지 재생성 | 예 |
| 기록 시각 | 2026-09-10 |

## 문제

Round 04의 원형 예시는 고유 시퀀스를 늘렸지만 평균 집합 일치도와 완전 일치 쌍을 악화시켰다. 모델에게 구조 선택을 맡긴 상태가 문제였다.

## 가설

코드가 카탈로그 원형 하나를 결정하고 sequence를 모델에게 지시하면, 모델의 기본 구성 습관과 무관하게 상품별 구조와 순서가 보존될 것이라고 가정했다.

## 실험 설계

이미지 SHA-256 기반으로 `count=1` 원형을 선택하고, 프롬프트에 선택된 sequence를 확정 구성으로 주입했다. 모델은 지정된 블록의 근거 있는 카피만 작성했으며 근거 없는 블록은 생략했다. 입력 6건과 이미지 재생성은 유지했다.

## 실행 명령

- 파일럿 생성기는 `scripts/run_eval_pilot.py`였다. 저장된 `run_index.json`에는 전체 CLI 인자가 보존되어 있지 않다.
- 구성 측정: `.venv/bin/python scripts/check_plan_diversity.py generated/evaluation/pilot-20260910-135605`
- 컷아웃 측정: `.venv/bin/python scripts/check_cutout_fidelity.py generated/evaluation/pilot-20260910-135605 --role hero`

## 측정 수치

유효 공통 블록은 `hero`와 `closing`을 제외한 종수다. 당시 구 기준은 평균 Jaccard `<=60%`, 전체 공통 블록 `<=4종`, 완전 일치 `0쌍`이었다.

| 지표 | 실측값 |
|---|---:|
| 평균 Jaccard | 72.4% |
| 유효 공통 블록 | 4종 |
| 완전 일치 쌍 | 1쌍 |
| 고유 시퀀스 | 5종/6건 |
| 최빈 반복 | 2회 |
| 길이 분포 | 8블록 3건, 10블록 3건 |
| 파일럿 성공 | 6/6 |
| 지시 순서 보존 | 6/6 |
| 근거 부족 생략 | 1건 |
| 컷아웃 게이트 | OK 6건, 부분 손실 0, 심각 손실 0 |
| 소요 시간 | 26.6분 |

## 판정

구 기준 `FAIL`이었다. 이전 차수보다 평균 Jaccard와 완전 일치 쌍은 낮아졌지만 평균 72.4%는 60%를 넘었고, 유효 공통 4종만으로도 전체 공통 상한을 넘는다. 완전 일치 쌍도 1쌍으로 0쌍 기준을 넘었다.

## 그 차수가 입증하거나 반증한 것

코드가 구성과 순서를 결정하면 지시 순서가 6/6건 보존되고 평균 79.8%→72.4%, 완전 일치 3→1쌍으로 수렴이 줄어든다는 가설은 입증됐다. 그러나 단일 해시 선택만으로 상품별 충돌을 없앤다는 가설은 반증됐다.

## 남은 한계

카탈로그의 `when`·`avoid_when` 조건을 사용하지 않아 해시 충돌이 남았다. 구조 지표만 있고 사람 검수 점수는 없었다.
