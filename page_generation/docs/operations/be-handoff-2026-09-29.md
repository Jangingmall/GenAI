## 한 줄 요약

AI 서버의 승인·콜백 처리를 고쳤습니다. **BE 가 확인해 주셔야 할 것이 3가지** 있습니다.

| # | 내용 | BE 조치 |
| --- | --- | --- |
| 1 | 렌더 도중 같은 승인을 다시 보내면 **409** 가 새로 옵니다 | 409 를 실패로 처리하지 말아 주세요 |
| 2 | 콜백에 **5xx·429 가 아닌 4xx** 로 응답하면 AI 가 **더 이상 재시도하지 않습니다** | 일시적인 오류는 5xx·429 로 응답해 주세요 |
| 3 | 드물게 **같은 `generation_id` 로 콜백이 두 번** 갈 수 있습니다 | 두 번째 콜백에 **409** 로 응답하는지 확인 부탁드립니다 |

## 1. 승인 재요청 — 409 "Approval is already in progress"

### 무엇이 바뀌었나

`POST /internal/v1/ai/detail-page-renders`(승인)는 렌더에 **수 분**이 걸립니다.
이전에는 렌더하는 동안 AI 서버 전체가 다른 요청에 응답하지 못했습니다. 이제는 렌더 중에도 상태 조회 등이 정상 응답합니다.

그 대신 **렌더가 진행 중일 때 같은 승인을 다시 보내면** 아래 응답이 옵니다.

```
HTTP 409
{"detail": "Approval is already in progress"}
```

| 상황 | 이전 | 이후 |
| --- | --- | --- |
| 렌더 중 같은 승인 재요청 | 첫 렌더가 끝날 때까지 응답이 지연된 뒤 200 | **즉시 409** "Approval is already in progress" |
| 렌더 완료 후 같은 승인 재요청 | 200 (저장된 결과) | 200 (저장된 결과) — 같음 |
| 같은 멱등키에 다른 내용 | 409 "Idempotency key conflict" | 409 "Idempotency key conflict" — 같음 |

### BE 에 부탁드리는 것

- **"Approval is already in progress" 409 는 실패가 아닙니다.** 잠시 뒤 **같은 멱등키·같은 내용**으로 다시 보내면 완료된 결과(200)를 받습니다
- 같은 409 라도 `"Idempotency key conflict"` 는 진짜 충돌입니다. **`detail` 로 구분**해 주세요
- BE 의 HTTP 타임아웃이 렌더 시간보다 짧아 재요청하는 구조라면 이 응답을 받게 됩니다

## 2. 콜백 재시도 규칙

### 무엇이 바뀌었나

AI 가 `POST {BACKEND_URL}/internal/generations/{generation_id}/completion` 으로 결과를 보낼 때,
BE 응답에 따라 재시도 여부를 정합니다. 이번에 **재시도하면 안 되는 응답까지 재시도하던 문제**를 고쳤습니다.

| BE 응답 | AI 동작 |
| --- | --- |
| 2xx | 전달 완료 |
| **409** | **이미 저장됨(`ALREADY_SAVED`)으로 보고 전달 완료** |
| 5xx, 429 | 재시도 |
| 네트워크 오류·타임아웃 | 재시도 |
| **그 외 4xx** (400·401·403·404·413·422 등) | **재시도 안 함 — 영구 실패로 기록** |

재시도는 **최대 8회**, 간격은 1초부터 두 배씩 늘어 최대 300초입니다.

| | 이전 | 이후 |
| --- | --- | --- |
| 4xx (409·429 제외) | 8회까지 재시도, **재시작할 때마다 다시 시도** | **즉시 중단** |
| 8회를 넘긴 실패 | **재시작·재처리 때마다 계속 다시 보냄** | 더 이상 보내지 않음 |

### BE 에 부탁드리는 것

**일시적인 문제는 5xx 또는 429 로 응답해 주세요.** 예를 들어 DB 가 잠깐 바쁘거나, 아직 준비가 안 된 상태를
4xx 로 응답하면 AI 는 영구 실패로 보고 다시 보내지 않습니다.

## 3. 같은 콜백이 두 번 갈 수 있는 경우 — 확인 요청

AI 서버가 **렌더 도중 재시작되면**, 그 승인을 "진행 중"에서 풀어서 BE 가 다시 요청할 수 있게 했습니다
(풀지 않으면 그 승인은 영원히 "진행 중"으로 막힙니다).

그런데 **첫 시도가 BE 콜백까지 마친 직후** 재시작됐다면, 다시 요청할 때 **같은 `generation_id` 로 콜백이
한 번 더** 갑니다. 드문 경우지만 가능합니다.

AI 는 콜백에 **409 가 오면 "이미 저장됨"으로 보고 끝냅니다.** 그래서

- BE 가 **이미 저장된 `generation_id` 에 409 를 돌려주면** 중복 저장 없이 끝납니다
- BE 가 **그대로 한 번 더 저장하면** 결과가 두 번 저장될 수 있습니다

저희는 BE 가 어느 쪽으로 동작하는지 **확인하지 못했습니다.**

## 4. BE 조치 없이 좋아지는 것

| 내용 | 효과 |
| --- | --- |
| 승인 렌더가 다른 요청을 막지 않음 | 렌더 중에도 상태 조회·초안 저장·헬스 체크가 정상 응답 |
| 같은 멱등키로 동시에 작업을 만들어도 1개만 생성 | 중복 작업 방지 (기존 계약과 같음, 보장이 강해짐) |
| 첫 콜백이 일시적으로 실패하면 재시도 예약 | 이전에는 재시도가 예약되지 않고 다음 재처리 때까지 대기했음 |

**API 요청·응답 형식은 바뀌지 않았습니다.** 새로 생긴 것은 1절의 409 응답 하나입니다.

## 5. 회신 부탁드립니다

1. **승인 409** — BE 가 승인 호출에서 409 를 받으면 지금 어떻게 처리하나요? `"Approval is already in progress"` 를 재시도로 처리할 수 있나요?
2. **콜백 응답 코드** — `/internal/generations/{generation_id}/completion` 이 일시적 오류에 어떤 코드를 돌려주나요? 4xx 로 돌려주는 일시적 오류가 있나요?
3. **중복 콜백** — 이미 저장된 `generation_id` 로 콜백이 다시 오면 409 를 돌려주나요?
4. **BE-11** — 승인·콜백 시점 A/B/C 결정은 여전히 기다리고 있습니다. 결정에 따라 1절의 승인 흐름이 다시 바뀔 수 있습니다.
