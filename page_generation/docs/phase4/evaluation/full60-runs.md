# 60건 전체 평가 산출물 보존 기록

두 벌의 60건 산출물을 디스크에 남긴다. 하나는 현재 코드가 실제로 내는 결과이고,
다른 하나는 되돌려진 컷아웃 추출기가 내던 결과다. 둘을 나란히 두는 이유는, 같은
60점에 대해 배경 제거를 시도했을 때와 포기했을 때가 어떻게 다른지가 이 두 디렉터리
바깥에는 남아 있지 않기 때문이다.

## 보존 대상

| 디렉터리 | 기준선 커밋 | 성격 |
| --- | --- | --- |
| `generated/evaluation/full60-20260910-204433` | `c1d413f` | **현재 유효 산출물.** 되돌린 추출기가 내는 결과와 같다. |
| `generated/evaluation/full60-v2-20260911-110752` | `696dd15` | **대조용.** 추출기 수정본이 내던 결과. 이 코드는 `162863d`로 되돌려졌다. |

두 실행 모두 60/60 성공, 실행 실패 0건이다. 1차는 3시간 52분(건당 227초), 2차는
4시간 13분(건당 253초)이 걸렸다. 2차가 느린 것은 폴백이 줄어 실제로 마스크를 만드는
건이 늘었기 때문이다.

## 두 실행의 차이

| 항목 | 1차 (현재 유효) | 2차 (대조용) |
| --- | ---: | ---: |
| 컷아웃 수행 | 9 / 60 (15.0%) | 24 / 60 (40.0%) |
| 컷아웃 미수행(폴백) | 51 | 36 |
| 게이트 OK | 3 | 13 |
| 부분 손실 | 4 | 2 |
| 심각 손실 | 0 | 1 |
| 배경 잔존 | 2 | 8 |

`fidelity_status` 전이는 `FALLBACK → VERIFIED` 15건, `VERIFIED → VERIFIED` 9건이고
역전이는 없었다. 즉 2차에서 나빠진 건은 없고 15건이 폴백을 벗어났다.

2차의 심각 손실 1건(`analysis-cma-109609`)은 실제 손실이 아니라 게이트의 오탐이다.
금 목걸이가 완전하게 잘려 나왔는데 전경 비율이 6.85%인 얇은 사슬이라 보존율이
13.4%로 계산됐다. 같은 건을 회귀 감사 도구는 침식 LOW·잔존 NONE으로 판정한다.
게이트의 성긴 제품 예외가 이 정도로 얇은 형태를 포괄하지 못한다.

## 되돌린 이유

자동 지표는 2차의 개선을 가리켰다. 그럼에도 관리자가 전후 비교를 육안으로 확인한 뒤
1차 산출물이 낫다고 판단해 추출기를 되돌렸다. 어떤 시각적 속성 때문인지는 기록되어
있지 않다. 게이트가 재는 것(제품 화소 보존, 배경 잔존)과 사람이 판단하는 품질이
일치하지 않는다는 사실만 확인됐고, 불일치의 원인은 미확인 상태다.

## 사용법

두 디렉터리는 비교 근거이므로 지우지 않는다. 컷아웃을 다시 손볼 때는 1차를 기준선으로
삼고, 2차는 "배경 제거를 더 적극적으로 했을 때 무엇이 벌어지는지"의 참고로 쓴다.

```
# 게이트 판정
.venv/bin/python scripts/check_cutout_fidelity.py <디렉터리> --role hero

# 두 실행 비교 (추출기를 직접 호출해 잰다)
.venv/bin/python scripts/compare_cutout_regression.py \
  --run-index <디렉터리>/run_index.json \
  --baseline docs/phase4/evaluation/cutout-baseline-metrics.json
```

정답 집합은 `cutout-ground-truth.md`에 있다. 1차 디렉터리의 냉동 산출물에서 도출한
것이라 코드가 바뀌어도 변하지 않는다.
