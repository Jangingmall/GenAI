- 대상: 현재 운영 구성 — 분석·카피 Qwen3.8-27B, 이미지 FLUX.2-klein-9B (로컬 MLX Serve / 서버 SGLang)
- 쓰는 법: 상세페이지 **한 건마다** 아래 「실행 기록」부터 끝까지 복사해 체크한다
- 기호: **[자동]** 코드가 이미 막는 것 — 로그에 실패가 없는지만 본다 / **[사람]** 눈으로 확인해야 하는 것 /
  ⚠️ 알려진 약점 또는 실제 실행에서 나온 결함

> 사진·페이지 품질은 자동 검사를 모두 통과해도 **관리자가 눈으로 확인하기 전에는 합격이 아니다.**

## 0. 먼저 돌릴 것 — 사진 출처와 실패 로그

```bash
OUT=<결과 폴더>          # result_summary.json, react_document.json 이 있는 폴더
python3 - "$OUT" <<'EOF'
import json, re, sys
out = sys.argv[1]
photos = json.load(open(f"{out}/result_summary.json"))["detail_page"]["photos"]
used = set(re.findall(r'"imageId": *"([^"]+)"', open(f"{out}/react_document.json").read()))
for p in photos:
    print(f'{p["photo_id"]:10} {p.get("asset_mode", ""):16} {"사용" if p["photo_id"] in used else "미사용"}')
EOF
grep -E "photo generation failed|is unavailable; using default" <실행 로그>
```

- 생성컷은 `asset_mode` 가 `generated_scene`(사용 장면) · `generated_view`(디테일 02~05) 여야 실제로 생성된 것이다.
  `source_crop` · `source_composite` 이면 **생성에 실패해 원본으로 대체된 것**이다
- `react_document` 의 `imageId` 만으로는 생성컷 사용 여부를 알 수 없다. 대체된 원본 크롭도 `detail-02` 같은 이름으로 들어간다
- 생성 실패는 `result_summary.json` 에 남지 않고 **실행 로그에만** 남는다 (`photo generation failed: photo_id=... error=...`)

## 1. 입력 사진

- [ ] [자동] 형식·크기·파일 서명·디코딩 검사 통과 (`validation.validate_source_image`)
- [ ] [사람] ⚠️ **실제 상품 사진인가.** 상품이 없는 사진에도 설명을 만들어 내며, 이를 막는 검사는 없다
- [ ] [사람] 판매자 입력(소재·기법·이력)이 사진과 모순되지 않는가. 불일치를 감지하는 기능은 없다

## 2. 분석·카피

- [ ] [자동] 스키마 강제 + 요약 500자 · 특징 5개 · 카피 8개 이하 (`validation.validate_product_profile`)
- [ ] [사람] 상품 종류 · 공예 판정이 맞는가
- [ ] [사람] ⚠️ **사진으로 확인되지 않는 사실을 단정하지 않는가** (소재 · 크기 · 원산지 · "○○년 전통" 등).
  유일한 자동 방어(`sanitize_profile_for_render`)는 모델의 `evidence` 자기신고에 의존하는데, 60건 평가에서
  196개 특징이 모두 `image-visible` 로 신고돼 **걸러낸 항목이 0개였다.** 사실상 사람만 막을 수 있는 항목이다
- [ ] [사람] 확인되지 않은 정보가 "확인 필요"로 남아 있는가 (기본 정보 표 · 관리 안내)
- [ ] [사람] ⚠️ **「색과 문양」의 색 이름과 색 견본이 같은 색인가.** 2026-09-30 합죽선 실행에서
  "흰색"이 회색, "연두색"이 남색 견본으로 나왔다 (원인 미확인)

## 3. 페이지 구성

- [ ] [자동] 대표(hero) 블록 맨 앞 · 마무리(closing) 블록 맨 끝 보정 (`validation.ensure_editorial_page_plan`)
- [ ] [사람] ⚠️ **요청한 사진이 없어 다른 사진으로 대체된 블록이 없는가.** 로그의
  `photo_id '...' requested by ... is unavailable; using default photo_id 'hero'` 로 확인한다.
  2026-09-30 합죽선 실행에서 「전체 모습」이 대표 사진으로 대체됐다
- [ ] [사람] 같은 사진이 여러 섹션에 반복되지 않는가 (갤러리 · 전체 모습 · 크기 섹션)
- [ ] [사람] 빈 섹션이나 내용 없이 제목만 있는 섹션이 없는가

## 4. 사진 — 원본 보존

- [ ] [자동] 생성컷은 원본 해시가 일치해야 통과하고, 불일치하면 거부된다 · 대표 사진은 원본 고정 (`source_photos.ProductFidelityValidator`)
- [ ] [자동] 생성 실패 시 원본 기반 사진으로 대체된다 (0번의 로그로 실패 여부 확인)
- [ ] [사람] 대표 사진이 원본 그대로인가
- [ ] [사람] **생성컷(사용 장면 · 디테일 02~05)에서 상품의 형태 · 무늬 · 색 · 낙관이 원본과 같은가.**
  공예품은 그림 · 무늬가 곧 상품이므로 가장 중요한 항목이다
- [ ] [사람] 생성컷이 실제로 페이지에 쓰였는가 (0번 스크립트: `generated_*` 이면서 `사용`)
- [ ] [사람] ⚠️ 누끼 합성 가장자리에 잘림 · 배경 잔여가 없는가. 원본에서 프레임 밖으로 잘린 상품은
  합성하면 직선 절단면이 그대로 보인다 (2026-09-30 합죽선 사용 장면)
- [ ] [사람] 배경 소품이 상품과 헷갈리지 않는가 (예: 도자기 상품인데 배경에 도자기 소품)

## 5. React 문서 · 렌더링

- [ ] [자동] `react_document` schema v2.0 — 허용 태그 · 트리 구조 · 안전한 URL · 색 값 형식 (`react_document.py`)
- [ ] [사람] PNG 와 `react_document` 의 사진 구성이 같은가 (갤러리는 두 경로가 같은 규칙 `resolve_gallery_photo_ids` 를 쓴다)
- [ ] [사람] 글자 넘침 · 잘림 · 겹침이 없는가
- [ ] [사람] 상세페이지 PNG 를 처음부터 끝까지 한 번 훑어봤는가

## 6. 승인 · BE 전달 (서버 실행일 때)

- [ ] [자동] 같은 멱등 키로는 작업 1건만 생성 · 렌더 중 같은 승인은 409 `Approval is already in progress`
- [ ] [자동] 콜백은 5xx · 429 일 때만 재시도, 그 밖의 4xx 는 영구 실패로 기록
- [ ] [사람] BE 에서 generation 이 `DRAFT_READY` → 승인 → `COMPLETED` 로 바뀌었는가
- [ ] [사람] 승인부터 콜백 완료까지 **300초**(BE 승인 호출 타임아웃) 안인가. 넘으면 BE 에
  `AI 렌더 승인 요청 실패` 로그가 남지만, 늦게 도착한 콜백으로 결과는 반영된다
- [ ] [사람] 콜백 영구 실패(`PERMANENT_FAILED`) 기록이 없는가
