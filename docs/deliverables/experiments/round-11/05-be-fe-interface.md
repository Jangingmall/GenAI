## 1. 변경 없음

이 차수는 BE/FE 인터페이스 계약을 건드리지 않았다. 직전 차수 계약을 그대로 유지한다.

`page_plan` 블록 어휘, `PageBlockVariant` 열거형, `react_document` 노드 스키마, `layout_id` 등 BE와 FE가 교환하는 데이터 명세에는 아무런 변화가 없다.

직전 10차에서 정립된 다음 인터페이스 계약이 완벽히 동일하게 유지된다:
- `react_document.json` 노드 트리 스키마 및 속성 구조 유지
- 10차에서 복구된 생성 이미지의 '참고용' 라벨 전달 계약(`product_generated=True`인 에셋 5종에 `PhotoAsset.label` 전달) 유지
- FE 렌더링 시맨틱 토큰(`--fill-neutral-impact`, `--font-white`) 유지

---

## 2. FE 소비 관점의 에셋 메타데이터 분포 변화

백엔드 파이프라인이 생성하여 FE에 전달하는 사진 에셋의 메타데이터 필드 중 `fidelity_status`와 `asset_mode`의 값 분포가 2차 실행 중 일시적으로 변동했으나, 되돌림 조치로 원복되었다.

### 1) 차수별 에셋 메타데이터 분포 대조

| 실행 시점 | 폴백 상태 (`FALLBACK` / `source`) | 컷아웃 상태 (`VERIFIED` / `cutout`) | 비고 |
| --- | ---: | ---: | --- |
| 60건 1차 실행 (`full60-20260910-204433`) | 51건 (85.0%) | 9건 (15.0%) | 10차 종료 기준선 |
| 60건 2차 실행 (`full60-v2-20260911-110752`) | 36건 (60.0%) | 24건 (40.0%) | 추출기 v2 적용 실험치 |
| **최종 되돌림 상태 (`162863d`)** | **51건 (85.0%)** | **9건 (15.0%)** | **1차 기준선으로 완전 복귀** |

### 2) FE 렌더러 동작 영향
- FE 렌더러(`html_renderer.py` 및 FE 컴포넌트)는 hero 블록에 삽입되는 이미지 에셋이 투명 알파 채널을 가진 누끼 컷(`asset_mode=cutout`)이든 불투명 배경을 가진 원본 컷(`asset_mode=source`)이든 상관없이 동일한 레이아웃 컨테이너 안에 정상 렌더링하도록 설계되어 있다.
- 따라서 추출기 수정 시 컷아웃 비율이 24건으로 증가했을 때나, 관리자 육안 판단으로 추출기를 되돌려 다시 51건이 원본 사진으로 전달될 때 모두 FE 화면이 깨지거나 런타임 렌더링 오류가 발생하는 문제는 전혀 발생하지 않았다.

## 3. 하위 호환성 여부

**100% 하위 호환 유지**.

BE-FE 간의 데이터 통신 명세, DTO 스키마, CSS 토큰 및 JSON 결과 파일 규격이 단 1줄도 변경되지 않았으므로, 기존 FE 클라이언트는 아무런 수정 없이 완벽하게 동작한다.
