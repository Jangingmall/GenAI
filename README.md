# 미담 (Midam) · AI 파트

> 스토리 중심 장인 공예 커머스의 AI 기능 저장소

---

## 1. 프로젝트 개요

**미담**은 국가 공인 장인과 공예 작가의 작품을 **그 서사와 함께** 파는 커머스다.

- **차별점:** 후기·판매량이 아니라 **작품의 의미와 장인의 서사**로 추천한다. 그래서 후기가
  0건인 신규·전통 장인의 작품도 노출된다.
- **AI 파트의 역할:** 자연어로 소비자의 의도를 이해해 의미 기반으로 작품을 추천하고,
  장인이 쓴 글·이미지를 바탕으로 상세페이지 초안을 생성한다.
- **원칙:** 없는 사실을 지어내지 않는 정직성, 장인이 직접 등록한 데이터 사용.

이 저장소는 두 AI 기능을 폴더로 나눠 관리하는 **모노레포**다.

```
midam/
├── chat_bot/            # AI 추천 챗봇
├── page_generation/     # AI 상세페이지 생성
├── README.md            
├── GIT_GUIDE.md         # 깃허브 협업 규칙
└── CODE_STYLE.md        # 코드 작성 규칙
```

## 2. 시스템 아키텍처

소비자·장인·프론트는 **백엔드만** 상대하고, AI 파트는 백엔드 뒤의 서버로서 백엔드하고만
통신한다. 두 AI 기능(챗봇 추천 / 상세페이지 생성)은 서로 직접
통신하지 않고 **백엔드를 통해 연결**된다.

```
[소비자]                              [장인]
   │ 자연어 질의                          │ 상품 이미지·설명 입력
   ▼                                     ▼
[프론트] ─────────────────────────── [프론트]
   │ 추천 요청                            │ 상세페이지 생성 요청
   ▼                                     ▼
┌───────────────────────── 백엔드 ─────────────────────────┐
│  세션·이력 관리 / 상품 상세 조립         상품 저장 / 결과 저장   │
│         │                                    │              │
│   (동기) │ 호출                        (비동기) │ 작업 생성      │
│         ▼                                    ▼              │
│   [챗봇 AI 서버]                      [상세페이지 AI 서버]      │
│    의도분류→검색→랭킹→생성            이미지분석→카피→렌더(PNG)   │
│         │ reply+products                     │ PNG+메타데이터   │
│         ▼                                    ▼              │
│    응답 반환                          결과 저장 API로 전달       │
└──────────────────────────────────────────────────────────┘
        │                                    │
        │ ◀── 상품 동기화(/ai/products) ──────┘
        │     (저장된 상품을 챗봇 검색 대상으로)
        ▼
   [챗봇 벡터DB]
```

### 두 AI 기능의 연결
```
[상세페이지 생성] → 백엔드에 상품 저장 → [백엔드가 챗봇 AI로 동기화] → 챗봇 검색 대상이 됨
```
상세페이지 생성이 만든 상품이 백엔드에 저장되고, 백엔드가 그 상품을 챗봇 AI의 벡터DB로
동기화(`/ai/products`)하면 비로소 챗봇이 추천할 수 있게 된다. 두 AI 서버는 서로를 직접
호출하지 않는다.

### 통신 방식 차이
| 기능 | 방식 | 이유 |
| :--- | :--- | :--- |
| 챗봇 추천 | 동기 (요청→즉시 응답) | 검색·랭킹 결과를 모아 바로 반환 |
| 상세페이지 생성 | 비동기 (작업 생성→폴링→완료) | 이미지 분석·렌더링에 시간 소요 |

### 책임 경계
| 파트 | 책임 |
| :--- | :--- |
| 프론트 | 입력 UI, 백엔드 호출, 결과 렌더링 |
| 백엔드 | 세션·대화이력 관리, AI 호출, 상품 상세 조립, **두 AI 기능 간 동기화** |
| 챗봇 AI | 자연어 이해·검색·랭킹·추천 생성, 자체 벡터DB 운영 |
| 상세페이지 AI | 이미지 분석·카피 생성·공예 조사·상세페이지 렌더링(PNG) |

### 기술 스택
| 구분 | 챗봇 추천 | 상세페이지 생성 |
| :--- | :--- | :--- |
| 서버 | FastAPI | FastAPI |
| LLM | Qwen3 8B (Ollama, 로컬) * | 외부 AI API (예: Gemini) |
| 임베딩 | BGE-M3 (1024차원) * | — |
| 검색 | pgvector + BM25(Kiwi) + RRF | — |
| DB | PostgreSQL 17 + pgvector | (상품 백엔드 DB 사용) |
 
> \* 챗봇 모델은 후보이며 목데이터 평가 후 확정한다.

## 3. AI 기능 범위

### 3-1. 추천 챗봇 (`chat_bot/`)

자연어 질의를 받아 의미 기반으로 작품을 추천한다.

**파이프라인 (5단계)**
```
자연어 입력
 → ① 의도분류·조건추출 (LLM)      가격·상황·취향 파악
 → ② 쿼리 임베딩                  자연어 → 벡터
 → ③ 하이브리드 검색              벡터 + BM25 + RRF, 가격 필터, 유사도 컷
 → ④ 등급 가중 랭킹               유사도 × 공인 등급, 최대 3개
 → ⑤ 근거 기반 생성 (LLM)         추천 이유·후속 질문 생성
 → 응답 { reply, intent, products, suggestions }
```

- **응답 방식:** 동기 (요청 → 즉시 응답)
- **구동:** 완전 로컬 (MacBook M4) — 외부 API·클라우드 미사용

### 3-2. 상세페이지 생성 (`page_generation/`)

장인이 입력한 이미지·글(제작 이야기·관리법)을 바탕으로 상세페이지 초안(HTML/CSS →
최종 PNG)을 생성한다. 매번 다른 문장이 나오는 게 정상이며, 원문·이미지에서 확인되지
않은 사실은 지어내지 않는다. 원본 제품 사진은 재생성하지 않고 원본을 보존한다.

- **응답 방식:** 비동기 (작업 생성 → 상태 폴링 → 완료)
- **구동:** 이미지 분석·생성에 **외부 AI API 활용** (예: Gemini).


### 공유 지점
두 기능은 **같은 입력**을 쓴다 — 장인이 상품 등록 시 쓴 자유서술(제작 이야기·관리법)이
챗봇의 검색 대상이자 상세페이지 생성의 재료다.

## 4. FE–BE–AI 통합 인터페이스

두 구간을 다른 깊이로 정의한다.
- **프론트 ↔ 백엔드:** 오가는 데이터 개요 (상세 규약은 백엔드 소관)
- **백엔드 ↔ AI:** 기능별 입출력 계약 (AI 파트가 확정)

### 4-1. 추천 흐름 (챗봇 · 동기)
```
FE → BE : 소비자 자연어 메시지
BE → AI : { session_id, message, history? }      # 원문 그대로, 조건 추출은 AI가
AI → BE : { reply, intent, products[], suggestions[] }
                products = [{ product_id, reason }]  (최대 3개)
BE → FE : reply + 카드(상품 상세 + reason)          # BE가 product_id로 상세 조립
```
> AI는 상품 상세(이미지·가격 등)를 반환하지 않는다. `product_id`와 `reason`만 넘기고,
> 백엔드가 자기 DB에서 상세를 조립한다.

### 4-2. 상품 동기화 흐름 (백엔드 → 챗봇 AI)
```
상품 등록/수정/삭제 시 백엔드가 챗봇 AI에 전달
  → AI DB 저장 → 임베딩 (저장 후 임베딩)
전달 데이터: 장인 정보 + 상품 정보(제작 이야기·관리법 포함)
```

### 4-3. 상세페이지 생성 흐름 (비동기)
```
FE → BE : 이미지 + 상품 설명
BE → AI : 작업 생성 (POST detail-page-jobs)
AI      : QUEUED → ANALYZING → ... → RENDERING → COMPLETED
BE      : 상태 폴링으로 진행 확인
AI → BE : 최종 결과(PNG·메타데이터)를 백엔드 저장 API로 전달
```

### 4-4. 세션·대화 이력 (챗봇)
- 세션 관리·대화 이력 저장은 **백엔드 담당.** 챗봇 AI는 무상태(stateless).
- 멀티턴이 필요하면 백엔드가 최근 대화(history)를 함께 넘긴다.

### 4-5. 응답 규약 (챗봇)
- 추천 응답은 항상 `{ reply, intent, products[], suggestions[] }` 구조.
- 검색 결과가 없어도 에러가 아니다 — `products: []` + 안내 `reply`로 정상 응답.

## 5. 개발 환경 & 협업

- **공통:** MacBook M4.
- **구동 방식은 기능마다 다름:** 챗봇은 완전 로컬, 상세페이지는 일부 외부 AI API 활용.
- 각 폴더는 **자체 가상환경** 을 갖는다 (기능별 의존성 분리). 저장소에 포함하지 않는다.
- 협업 규칙: **`GIT_GUIDE.md`**(브랜치·커밋·PR), **`CODE_STYLE.md`**(스타일·네이밍).
  - `main` 직접 커밋 금지, `feat/`·`fix/` 브랜치 → PR 병합.
  - `.env`·가상환경·모델 캐시는 커밋하지 않는다.
